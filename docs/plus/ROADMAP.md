# CrossPoint Plus: roadmap

Личная прошивка для Xteink X4 Pro на основе CrossPoint Reader: читалка и библиотека CrossPoint плюс быстрые заметки
в Markdown со своей клавиатурой. Как устроен код — [ARCHITECTURE.md](ARCHITECTURE.md), набор текста —
[TYPING.md](TYPING.md).

## Принципы

1. **Просто, быстро, минималистично, в стиле системы.** Скорость и точность набора важнее богатства функций.
2. **Только X4 Pro и только сенсор** (боковые кнопки и подсветка выбора остаются для тех, кто ими пользуется).
3. **Файлы — источник истины.** Заметка — обычный `.md` в `/notes`, который читается и правится с компьютера.
4. **Сначала замер, потом оптимизация.** Скорость набора проверяется на устройстве.
5. **Минимум своего кода поверх CrossPoint**: удаляем ненужное целиком, новое пишем в отдельных модулях.

## Как ведём проект

**Задача готова**, когда сборка и тесты на компьютере проходят, автор проверил её на устройстве по короткому чек-листу,
задержка набора не выросла, решение записано в журнал, версия поднята и на карте лежит один файл прошивки
(`crosspoint-plus-x4pro.bin`).

**Релиз готов**, когда CI зелёный, опубликован релиз с заметками, OTA-обновление с прошлой версии проверено, в README
есть установка и скриншоты, а настройки по умолчанию разумны.

Версии: `<версия CrossPoint>-plus.<N>`. Работа идёт в `main`; релиз — пуш тега `*-plus.*`.

## Что дальше

Порядок: выделение в заметках, выделения в книгах, свой сервер, затем публичный релиз. Каждый подэтап — отдельная
прошивка, которую автор проверяет на устройстве.

### Этап 6. Выделение в заметках
- 6.1 ✅ Модель выделения и внутренний буфер обмена, тесты на компьютере.
- 6.2 ✅ Жесты: двойной тап — слово, удержание — слово и ручки; ручки тянутся пальцем через строки; тап мимо снимает
  выделение. Выделенное инвертировано.
- 6.3 ✅ Панель над клавиатурой при выделении: «Копировать», «Вырезать», «Вставить», «Выделить всё»; удержание на курсоре
  без выделения — «Вставить».
- 6.4 Вставка из буфера в системных полях ввода (Wi‑Fi, поиск).
- 6.5 Чистота набора: найти причину шумов при наборе в ночном режиме и исправить; в «Система → Клавиатура» —
  настройки обновления экрана при наборе (быстрее или чище, пауза до чистого кадра).

### Этап 7. Выделения и комментарии в книгах
- 7.1 Выбор фрагмента на странице: удержание на слове, ручки (на основе экрана выбора слова для словаря).
- 7.2 Хранение: файл на книгу, якоря через `lib/ReadingPosition`; выделения переживают смену шрифта и размера, тесты.
- 7.3 Отображение в едином стиле с заметками: инвертирование или подчёркивание — одна настройка для заметок и книг;
  значок комментария на полях.
- 7.4 Меню по выделению: «Выделить», «Комментарий», «Словарь», «Копировать». Комментарий пишется в редакторе заметок.
- 7.5 Управление: тап по подчёркнутому — комментарий, «Изменить», «Удалить»; в меню читалки «Выделения» — список
  по порядку в книге (цитата, начало комментария, процент), тап — переход, удержание — изменить или удалить; тот же
  список по удержанию книги в библиотеке.

### Этап 8. Свой сервер: SilverBullet, статьи и новости
Всё, что требует интернета, готовит домашний сервер автора; устройство только забирает файлы по Wi‑Fi. Сначала —
обсуждение дизайна.
- 8.1 Подключение: адрес сервера и токен в настройках, проверка связи.
- 8.2 Синхронизация с SilverBullet: файлы по HTTP (`/.fs/…`), двусторонняя по времени изменения, правила конфликтов;
  `/notes` с выделениями, вручную из меню, затем автоматически при Wi‑Fi.
- 8.3 Статьи «прочитать позже»: ссылка уходит на сервер (например, из SilverBullet или с телефона), сервер вырезает
  текст и делает EPUB, устройство скачивает в `/articles`.
- 8.4 Новости: сервер раз в день собирает RSS (например, РБК) в один выпуск, устройство скачивает в `/news`; старые
  выпуски не копятся.

### Этап 5. Публичный релиз
- 5.1 CI зелёный: разобрать падение cppcheck на GitHub.
- 5.2 README: установка с нуля и через OTA, фото экранов.
- 5.3 Заметки к релизу, тег `1.6.5-plus.N`, релиз на GitHub.
- 5.4 Проверка OTA: следующая версия ставится с опубликованной.

### Бэклог идей
- Календарь с текущей датой (часы на устройстве есть).
- Регламент обновления на новые версии CrossPoint.

### Формат файла выделений
`/notes/highlights/<имя файла книги>.md` — обычный Markdown, читается и правится с компьютера и в SilverBullet. Файл —
единственный источник истины: правка комментария на компьютере видна на устройстве. Якорь в HTML-комментарии,
который Markdown не показывает:

```markdown
# Название книги

> Выделенный фрагмент.

Комментарий.
<!-- cp 4 /body/div[2]/p[14]:12 /body/div[2]/p[14]:58 -->
```
